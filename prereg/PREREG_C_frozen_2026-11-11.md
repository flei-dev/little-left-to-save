## 2. 能耗模型

### 公式
设备能耗由四部分相加：

- 射频：状态机模型（升级 → 下载 → 尾巴 → 空闲）。下载时功率 = β + α·吞吐。
- 播放：p_base·观看秒数 + c·解码的 MB 数 + 解码额外功率·观看秒数。
- 卡顿：p_stall·卡顿秒数。

### E1 网格（共 75 个点）
设备播放功率固定为 p_base = p_stall = 1.10 W（COCONUT 实测），α = 0。其余三个参数取：

- 每 MB 解码能耗 c ∈ {0.0444, 0.1, 0.2, 0.4, 0.65} J/MB。
- 下载后尾巴 (T, P) ∈ {(0, 0), (1 s, 0.25 W), (5 s, 1.06 W), (11.6 s, 1.06 W), (20 s, 2.12 W)}。
  - T ≤ 1 s 的点：无升级时延，空闲功率为 0（与实测一致）。
  - 其余点：升级 0.26 s，功率按尾巴功率等比例。
- 下载基础功率 β ∈ {0.65（实测）, 1.29（Huang'12 LTE）, 2.58} W。

### 4 个锚点
| 名称 | 设备 | 射频 | 备注 |
|---|---|---|---|
| meas | 新手机 | 实测 LTE | 等于网格点 c=0.0444、T=1、β=0.65 |
| modern_lte | 新手机 | 文献 LTE | |
| modern_5g | 新手机 | 文献推算 5G NSA | 尾巴 20 s、功率 2 倍 |
| legacy_lte | Galaxy S4 | 文献 LTE | 以往大多数工作的设定 |

### E4 的 AV1 解码额外功率（相对 H.264 硬解，1080p）
| 设定 | 额外功率 | 依据 |
|---|---|---|
| 硬解 | 0 | |
| dav1d | 0.115 W | 本机实测 |
| 系统解码器 | 0.69 W | 本机实测 |
| COCONUT 软解 | 1.43 W | COCONUT |

- 主设定：额外功率与分辨率（像素数）成正比。
- 敏感性：与分辨率无关（flat）。
- 射频：实测 LTE（主）；文献 LTE（敏感性）。

## 3. 方法网格（代码 `svs/grids.py`，事先固定）

λ 网格 = {0, 0.01, 0.02, 0.05, 0.1, 0.2, 0.4, 0.8, 1.6, 3.2, 6.4}。

### 短视频
- 不感知能耗：
  - Fixed：16 个参数点。
  - Dashlet：12 个。
  - PDAS：9 个。
- 感知能耗：
  - DashletE：2 × λ 网格。
  - BurstE：6 × λ 网格。
  - SPARE：λ 网格。
- 先知参照（知道每条视频会看多久，以及未来 2 s 的吞吐）：
  - O-SPARE：nbar ∈ {1, 2, 4, 8} × λ 网格。
  - O-Burst：6 × λ 网格。
- E2 分解：Ow-*（只知道观看时长）和 Ot-*（只知道吞吐），与 O-* 相同网格。

### 长视频
缓冲上限 B ∈ {30, 60, 120} s。

- 不感知能耗：
  - Rate：安全系数 {0.6, 0.8, 0.9, 1.0} × B。
  - BBA：(储备, 缓冲垫) ∈ {(5, 10), (10, 20), (5, 30)} × B。
  - BOLA：γp ∈ {1, 2, 5, 10} × B。
  - MPC：每个 B 一个点。
- 感知能耗：
  - MPC-E：λ > 0 × B。
  - BurstMPC：(L, H) ∈ {(10, 60), (30, 60), (20, 120), (60, 120)} × λ 网格。
- 先知参照（按真实未来吞吐模拟每个计划）：
  - O-MPC：λ 网格 × B。
  - O-BurstMPC：4 组 (L, H) × λ 网格。

### 关于先知参照
先知参照只是参照值，论文里称"clairvoyant reference"，不称最优解。

## 4. 主要指标

### 计算方法
- 每个能耗模型（E4 还要分每种编码模式），分别对每个参数点求评估会话的平均每分钟 QoE（SQoE-III，手机 VMAF）和平均每分钟设备能耗。
- 定义三个集合：
  - U = 不感知能耗的全部参数点；
  - A = U + 感知能耗的参数点；
  - O = A + 先知参照。
- 前沿：取帕累托前沿，相邻点之间线性插值。插值点可以通过在会话之间分时使用两个配置达到。
- 剩余节能空间：
  - H_aware = 对 U 前沿上的每个点 (q, E_U)，计算 1 − E_A(q)/E_U，再取平均。
  - H_oracle：同上，把 A 换成 O。
- 次要指标：
  - Htop：只看 U 的最高 QoE 点。
  - Hdata：把能耗换成流量。
  - E2 分解：H_watchonly、H_thronly。
- 不确定性：按会话自助法（E1/E2/E3/E5 各 500 次，E4 300 次），报告 95% 百分位区间。

### E3：DRL 与规则方法比较
- 规则包络 = U ∪ A。
- 主指标 G_drl：把 DRL 加进规则包络后，在规则前沿各点上的平均节能，即 H(规则 → 规则 ∪ DRL)。这个值 ≥ 0。
- 辅助指标：
  - S_drl：DRL 前沿相对规则包络的平均节省，只在 DRL 能达到的 QoE 上计算；
  - 覆盖率：规则前沿上 DRL 能达到的点所占比例；
  - 两者的最高 QoE。

### E4：编码格式
| 指标 | 含义 |
|---|---|
| av1_vs_h264 | 只用 AV1 相对只用 H.264 |
| both_vs_bestfixed | 两种编码都可选，相对固定一种编码的最好包络 |
| both_vs_caprule | 相对"有 AV1 硬解才用 AV1"的规则 |
| greedy_vs_h264 | 不感知能耗、只按画质选编码，相对只用 H.264 |
| data_* | 对应的流量节省 |

## 5. 事先写定的判定规则

**C1（新手机上剩得不多）**
- 条件：meas 下，短视频和长视频的 H_aware 的 95% 上限都 < 5%。
- 满足：写"在实测参数下，感知能耗的方法最多只能再省 5% 以内"。
- 不满足：只报告数值，不写这句话。

**C2（以往设定高估）**
- 报告 legacy_lte 与 meas 的 H_aware 之比（点估计）。
- 只有 legacy 的 95% 下限 > meas 的 95% 上限时，才写"显著更大"。

**C3（节能空间地图）**
- 报告 75 个网格点的 H_aware 和 H_oracle。
- "有实际意义的节能空间"指 H_aware 的 95% 下限 ≥ 10%，列出满足条件的区域。
- 用 Spearman 相关报告 H 与尾巴能量、β、c 的单调关系（描述性）。

**C4（与先知参照的差距）**
- 报告每个锚点的 H_oracle − H_aware 和 H_aware/H_oracle，以及 E2 分解。
- 不预设方向。

**C5（DRL）**

每个形态 × 每个 regime 按下表判定：

| 条件 | 结论 |
|---|---|
| G_drl 的 95% 上限 < 2% | DRL 没有超过调好的规则方法 |
| G_drl 的 95% 下限 > 2% | DRL 带来了规则方法没有的节能 |
| 其他 | 不确定 |

**C6（编码格式）**

| 条件 | 结论 |
|---|---|
| dav1d 或系统解码器设定下，某个网络集上 both_vs_caprule 的 95% 下限 ≥ 5% | 值得做"感知解码能耗的编码选择" |
| 否则 | 只报告数值 |

另外，报告 greedy_vs_h264 在没有 AV1 硬解的设定下是否为负，即只按画质切换编码是否反而费电。

**C7（稳健性）**
- 在 E5 的每个变体下重算 meas 的 H_aware：2 s 切片、标准 VMAF、5G 轨迹、old 轨迹、按留存曲线抽样观看时长。
- 只有 C1 在所有变体下都成立，才写"稳健"。否则写明在哪些变体下不成立。
- 长视频还按 9 个体裁分组报告（描述性）。
